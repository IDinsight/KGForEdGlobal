# Python Documentation Style

- Describe public API purpose, parameters, defaults, return/yield values, and
  meaningful types in the project's established docstring convention, subject to
  an explicitly selected compatible user style.
- Explain relevant exceptions and when they occur, side effects, mutation,
  resource ownership, and async/generator behavior where readers need them.
- Keep docstrings consistent with signatures and actual behavior; avoid merely
  repeating annotations or implementation details without value to callers.
- Use focused, realistic examples with necessary imports and setup. Document
  observed outputs only when established; distinguish illustrative usage from
  executed checks. Respect existing docstring rendering and doctest tooling.
- These are documentation rules, not function-design or coding preferences.
