# HTML Documentation Style

- Provide accurate markup examples with enough surrounding structure to show
  valid use. Follow the project's element and component naming conventions.
- Explain component usage, required content/attributes, nesting, and relevant
  structural constraints without prescribing a new component architecture.
- Include relevant accessibility instructions: semantic elements, labels,
  keyboard/focus expectations, and appropriate attribute usage. Match actual
  component support; do not claim accessibility compliance from a markup sample.
- Keep examples usable in their documented context and references current.
