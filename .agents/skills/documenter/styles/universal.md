# Universal Documentation Style

Always load this file. It governs discretionary documentation style, subject to
correctness, ownership, authoritative project constraints, and protocol conflict
handling.

- Use plain, natural-sounding language. Avoid overloaded jargon, AI speak, and
  unnecessarily complicated prose.
- Retain necessary technical terms and explain them when the audience needs it.
- Give accurate, audience-appropriate instructions and useful examples grounded
  in actual behavior. Make prerequisites, limitations, and uncertainty clear.
- Use consistent terminology, valid references, and minimal duplication.
  Preserve established documentation conventions and useful structure.
- Organize explanations by purpose: help the reader understand, start, perform a
  task, or look up a contract. Do not impose every section on every document.
- Preserve useful user-authored content and avoid cosmetic rewrites. Prefer one
  maintained explanation with links over repeated instructions.
- Distinguish intended behavior, observed behavior, and unverified assumptions.
  Never invent outputs, checks, or guarantees to make an example look complete.
