# CSS Documentation Style

- Document styling APIs, tokens, custom properties, defaults, supported values,
  and the intended override points using established project terminology.
- Explain theme behavior, inheritance/cascade or scoping assumptions, and layout
  requirements when consumers need them to use the styles correctly.
- Make non-obvious constraints explicit, including component dependencies,
  responsive assumptions, and relevant accessibility effects.
- Keep examples consistent with actual selectors and supported themes. Describe
  the existing styling contract without imposing implementation preferences or
  changing tokens, layout behavior, or tooling.
