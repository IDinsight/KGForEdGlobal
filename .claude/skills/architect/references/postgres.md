# PostgreSQL

Read when the technical design must choose, configure, or change PostgreSQL as a
data store. Record the resulting decisions in the technical design; Developer
implements them. Setup steps here are implementation detail for Developer once
the design selects this option. This reference never overrides the protocol, the
completed scope, established project constraints, or official documentation for
the installed version.

Read alongside [`databases.md`](databases.md), which holds the engine-neutral
principles. The examples use the Python default stack: SQLModel on SQLAlchemy,
the psycopg 3 driver, and Alembic. Translate them for other stacks.

Section notes about maturity levels refer to the Scoper ladder in
[`../../scoper/references/maturity-levels.md`](../../scoper/references/maturity-levels.md).
They describe when a practice is commonly expected and are never a gate.

## Version Notes

When this guidance was written, PostgreSQL 18 (released September 2025) was the
current major release, and versions 14 to 18 were supported. Each major version
receives five years of support, with no separate LTS designation. PostgreSQL 14
reaches end of life in November 2026. Check the versioning policy for the
current list before recording a version in the design.

## Database Names

Create the databases with the names from [`databases.md`](databases.md). At
maturity Level 1 (spike) this is usually all that is needed, with the names
recorded in `.env.example` as placeholders.

```sh
createdb {project_name}_dev
createdb {project_name}_test
```

## Connectivity and Migrations

Commonly expected from maturity Level 2 (connected prototype).

### Local Docker Compose

```yaml
services:
  db:
    image: postgres:18
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: {project_name}_dev
    volumes:
      # PostgreSQL 18+ images: mount the parent directory, not .../data
      - postgres_data:/var/lib/postgresql
    ports:
      - "5432:5432"
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U postgres"]
      interval: 5s
      timeout: 5s
      retries: 5

  db-test:
    image: postgres:18
    environment:
      POSTGRES_USER: postgres
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: {project_name}_test
    ports:
      - "5433:5432" # different host port
    # no volume: the test database is ephemeral

volumes:
  postgres_data:
```

The official image changed its data layout in PostgreSQL 18. `PGDATA` is now
version-specific (`/var/lib/postgresql/18/docker`) and the declared volume moved
up to `/var/lib/postgresql`. Mount `/var/lib/postgresql/data` only for images up
to version 17. Upgrading an existing local volume across this boundary needs a
data move or dump and restore, not just an image tag change.

### Environment Variables

Add to `.env.example`, with the password left as a placeholder:

```dotenv
DATABASE_URL=postgresql+psycopg://postgres:[DB_PASSWORD]@localhost:5432/{project_name}_dev
TEST_DATABASE_URL=postgresql+psycopg://postgres:[DB_PASSWORD]@localhost:5433/{project_name}_test
DB_CONNECT_RETRIES=5
DB_CONNECT_RETRY_INTERVAL_SECONDS=2
```

<!-- markdownlint-enable MD013 -->

Use the psycopg 3 driver. The SQLAlchemy URL prefix is `postgresql+psycopg://`.

### Connection with Startup Retry

```python
# utils/database.py: key pattern only
engine = create_engine(url, pool_pre_ping=True)

for attempt in range(1, retries + 1):
    try:
        with engine.connect() as conn:
            conn.execute(text("SELECT 1"))
        break
    except Exception:
        logger.warning("Database not ready (%d/%d)", attempt, retries)
        if attempt == retries:
            raise
        time.sleep(interval * attempt)
```

### Alembic

```sh
uv add alembic
uv run alembic init migrations
```

Configure `migrations/env.py` to read `DATABASE_URL` from settings and point
`target_metadata` at `SQLModel.metadata`. Create an empty initial migration to
prove the toolchain before writing any models.

If a generated migration contains `drop_table`, `drop_column`, or `drop_index`,
do not run it automatically. Present the command to a person and require manual
execution after a verified backup. This applies equally to platform pre-deploy
steps and CI jobs that run migrations.

## Constraints, Indexes, and Test Isolation

Commonly expected from maturity Level 3 (internally testable).

- Define NOT NULL, unique, and foreign key constraints in migration files, not
  only in application code.
- Index the columns that frequent WHERE, JOIN, and ORDER BY clauses depend on
  when the access pattern justifies the write cost; check the query plan for
  performance-sensitive queries rather than indexing reflexively. Review
  autogenerated migrations for missing or redundant indexes before applying
  them.

The recommended test isolation is a transaction rolled back after each test,
with application commits turned into savepoints so the rollback undoes them.
Tester owns the fixtures; `../../tester/references/fastapi-testing.md` shows the
pattern.

Never substitute SQLite for PostgreSQL in tests. The dialects differ.

## Production Pool and Observability

Commonly expected from maturity Level 4 (pre-production).

### Pool Configuration

```dotenv
DB_POOL_SIZE=10
DB_MAX_OVERFLOW=20
DB_POOL_RECYCLE=1800
DB_POOL_TIMEOUT=30
DB_SLOW_QUERY_MS=500
```

Add all of these to `.env.example`. Size them with the formula in
[`databases.md`](databases.md#connection-pooling).

```python
engine = create_engine(
    url,
    pool_size=settings.db_pool_size,
    max_overflow=settings.db_max_overflow,
    pool_recycle=settings.db_pool_recycle,
    pool_timeout=settings.db_pool_timeout,
    pool_pre_ping=True,
)
```

### Slow Query Logging

SQLAlchemy connection events can time every statement:

```python
@event.listens_for(engine, "before_cursor_execute")
def _before(conn, cursor, statement, parameters, context, executemany):
    conn.info.setdefault("query_start_time", []).append(time.monotonic())


@event.listens_for(engine, "after_cursor_execute")
def _after(conn, cursor, statement, parameters, context, executemany):
    started = conn.info["query_start_time"].pop()
    elapsed_ms = (time.monotonic() - started) * 1000
    if elapsed_ms > settings.db_slow_query_ms:
        logger.warning(
            "Slow query (%.1fms): %s", elapsed_ms, statement[:200]
        )
```

Log the statement text only. Never log bound parameters, which can hold personal
data or credentials.

### Health Check

The health check executes a real query and returns 503 on failure:

```python
@app.get("/health")
def health():
    try:
        with Session(engine) as s:
            s.exec(text("SELECT 1"))
        db_status = "ok"
    except Exception:
        db_status = "unreachable"
    ok = db_status == "ok"
    return JSONResponse(
        status_code=200 if ok else 503,
        content={
            "status": "ok" if ok else "degraded",
            "checks": {"database": db_status},
        },
    )
```

## Schema Isolation and Hardening

Commonly expected at maturity Level 5 (public production).

### Application Schema and Roles

Use a dedicated schema instead of `public`, and separate the role that runs
migrations from the role the application uses at runtime. The runtime role then
holds only data privileges.

```sql
-- run once as a superuser during provisioning
CREATE SCHEMA IF NOT EXISTS app AUTHORIZATION {migration_role};
GRANT USAGE ON SCHEMA app TO {app_role};
ALTER DEFAULT PRIVILEGES FOR ROLE {migration_role} IN SCHEMA app
  GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO {app_role};
ALTER DEFAULT PRIVILEGES FOR ROLE {migration_role} IN SCHEMA app
  GRANT USAGE, SELECT ON SEQUENCES TO {app_role};
REVOKE ALL ON SCHEMA public FROM {app_role};
ALTER ROLE {app_role} SET search_path = app;
ALTER ROLE {migration_role} SET search_path = app;
```

Setting `search_path` on the role avoids encoding it in every connection URL. If
it must go in the URL, append `?options=-csearch_path%3Dapp`.

### Additional Hardening

- Require TLS. `sslmode=require` encrypts the connection but does not verify the
  server. Prefer `sslmode=verify-full` with the provider's CA certificate where
  available.
- Set `ssl_min_protocol_version = 'TLSv1.2'` in `postgresql.conf` to reject
  older TLS handshakes.
- Keep `password_encryption = scram-sha-256`, the default since PostgreSQL 14.
  MD5 password authentication is deprecated as of PostgreSQL 18.
- Set `idle_in_transaction_session_timeout` in `postgresql.conf` or with
  `ALTER ROLE` so hung transactions are terminated.
- Enable `pg_stat_statements` for production query analysis. It identifies slow
  and frequently run queries.
- Set `authentication_timeout = 30s` to shorten the exposure window for slow or
  hung authentication attempts.
- The runtime role has only `SELECT`, `INSERT`, `UPDATE`, and `DELETE` on
  application tables: no `CREATE`, no `DROP`, and never superuser.
- Run automated daily backups and verify that they restore.

Managed providers, such as Railway PostgreSQL or Cloud SQL, may not expose
`postgresql.conf`. Use the provider's database flags or role-level settings, and
record in the design which settings the provider controls.
